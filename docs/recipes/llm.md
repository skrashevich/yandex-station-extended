# Своя LLM вместо Алисы

ВЫ можете настроить работу колонки на ответы своей моделью — ChatGPT, Claude, Ollama вместо штатной Алисы.
Способов три, и они сильно разные: один оставляет голос Алисы и облако Яндекса, другой подключает к колонке ChatGPT Voice.

!!! info "Информация"
    Третий способ, это установка и настройка self-hosted или облачного бэкенда который полностью заменяет инфраструктуру Яндекса. Подробнее про бэкенды [здесь](../recipes/bekend-self-hosted/).



## Какой способ выбрать { #compare }

| | [Quasar Bridge](#quasar-bridge) | [ChatGPT Voice](#chatgpt-web) |
|---|---|---|
| Чей голос отвечает | Алисы | ChatGPT |
| Умный дом Яндекса | работает | работает вне чата |
| Музыка Яндекса | работает | ставится на паузу |
| Нужен интернет | да | да |
| Что нужно держать включённым | при установке Quasar Bridge на колонку — только колонку; при установке на компьютер — колонку и этот компьютер | колонку; для моста — ещё Linux-ПК |
| Проверено на | Станция 2, Quasar 3.21; Миди — установка и автозапуск | Лайт 2 (Plum), 0.369.1.50; Лайт 1 и Станция 2 — данные авторов адаптаций |

Quasar Bridge подменяет адрес сервера голосового соединения — ключи
`uniProxyUrl` и `uniProxyQuicUrl` в файле `/system/vendor/quasar/quasar.cfg`. Файл лежит
на системном разделе и правится после `mount -o remount,rw /`. ChatGPT Voice
адрес не меняет: он работает со звуком на самой колонке. Как устроена передача голоса от
микрофона до ответа, описано в [голосовом тракте Алисы](../internals/voice.md).

!!! danger "Quasar Bridge меняет системный конфиг"
    Перед подключением снимите копию `quasar.cfg`, чтобы потом вернуть адреса:

    ```sh
    adb pull /system/vendor/quasar/quasar.cfg ./quasar.cfg.orig
    ```

    Все три проекта неофициальные, с Яндексом не связаны и годятся только для своих
    устройств.

## Quasar Bridge: своя LLM с голосом Алисы { #quasar-bridge }

[Quasar Bridge](https://github.com/skrashevich/quasar-bridge) — прокси на Go, который
распределяет запросы колонки между своей моделью, Home Assistant и Яндексом. Распознавание
речи и озвучивание ответов остаются облачными, поэтому отвечает голос Алисы.

### Как подключить { #bridge-setup }

1. Получите root и доступ по SSH.
2. Выберите, где запускать прокси: на отдельном хосте или на самой колонке через
   [YAM](packagemanagers.md). Готовые пакеты для Linux ARM64 и контрольные суммы лежат в
   [релизах проекта](https://github.com/skrashevich/quasar-bridge/releases).
3. Укажите в конфигурации OpenAI-совместимый адрес модели. Для управления домом
   подключите [HA MCP](https://github.com/homeassistant-ai/ha-mcp) и опишите правила
   маршрутизации под свои запросы.
4. Направьте `uniProxyUrl` и `uniProxyQuicUrl` колонки на свой сервер по
   [инструкции проекта](https://github.com/skrashevich/quasar-bridge#readme). Установка
   пакета сама по себе адрес не меняет.

### Как распределяются запросы { #bridge-routing }

| Запрос | Кто отвечает |
|---|---|
| Управление устройствами и вопросы об их состоянии | Home Assistant, формулирует своя модель |
| Сложные вопросы, «спроси нейросеть», чтение страниц и истории | своя модель |
| Музыка, погода, таймеры и остальные обычные команды | Яндекс |

Правила описываются в JSON и перечитываются без пересборки сервера. Если облачная Алиса
отказалась отвечать, запрос можно передать своей модели. Для подряд идущих локальных
вопросов сохраняется контекст диалога; модели доступны чтение страниц по адресу, поиск по
журналу запросов и текущее время. Журнал по умолчанию выключен.

### Ограничения { #bridge-limits }

- Привязка колонки к аккаунту Яндекса сохраняется: распознавание и синтез речи идут через
  облако даже тогда, когда отвечает своя модель.
- Прокси на колонке не означает модель на колонке: её API должен быть доступен по сети.
- Пакет собран для ARM64 и проверен на Станции 2. Остальные модели не проверялись.
- Медленный ответ модели прикрывается настраиваемым беззвучным ожиданием, но общий лимит
  обработки запроса остаётся.
- Пакет `.yap` ставится только в YAM 0.1.x со службой `yamd`. `hackalice.me/install.sh`
  ставит YAM 0.2, у которого совместимость со старыми пакетами потеряна. Ставьте 0.1.15
  установщиком из его тега, а в `settings.toml` `yamd` выключите автообновление
  (`[updates] enabled = false`), иначе `yamd` попытается обновиться до последнего релиза:

    ```sh
    curl -fsSL https://raw.githubusercontent.com/nyakokitsu/yam/v0.1.15/install.sh | sh -s -- v0.1.15
    ```

- С Ollama берите модель без рассуждений. Тег `qwen3:30b-a3b` рассуждает, и отключить это
  через Ollama не удалось: ответ обрезается лимитом токенов или рассуждения попадают в
  озвучку. `qwen3:30b-a3b-instruct-2507-q4_K_M` отвечает сразу, около 1,6 с на M1 Max.
  Проверено на Станции 2 (прошивка 0.369.1.46), Quasar Bridge 0.4.2, октябрь 2026.

## ChatGPT Voice: нативный режим и мост { #chatgpt-web }

[Alisa Voice][alisa-voice] подключает микрофоны и динамик Лайт 1, Лайт 2 и Станции 2
к ChatGPT Voice. В [версии 0.3.3][alisa-release] доступны два режима:

| Режим | Где работает клиент | Что нужно держать включённым |
|---|---|---|
| Нативный | на Лайт 1, Лайт 2 или Станции 2; установка с Linux или Windows | только колонку |
| Мост | сайт ChatGPT в фоновом Chromium на Linux-ПК; колонка — Лайт 2 | колонку и ПК |

Распознавание речи и ответы ChatGPT в обоих случаях остаются облачными. Используется
аккаунт ChatGPT, API-ключ не нужен.

**Проверено на:** Станция Лайт 2 YNDX-00028 (Plum), прошивка
`0.369.1.50.4794654278.20261021.133`, CachyOS x86_64, 30 октября 2026.
Free и Plus проверены в обоих режимах Linux; нативная установка и обновление — также
на [Windows 11 x64 с Edge][alisa-windows]. Результаты Лайт 1 получены от
[автора адаптации][alisa-lite1] на одной сборке; программное отключение её микрофона
в GPT отдельно не проверено. Живой Go-аккаунт не проверен.
[Результаты проверки Linux][alisa-validation].

Обновление 0.3.2 → 0.3.3 проверено на Лайт 2, 1 ноября 2026: голосовой ответ,
обработанный микрофон, возврат штатной озвучки Алисы и автозапуск после перезагрузки.
Вход, чаты и настройки при обновлении сохранились. [Результаты 0.3.3][alisa-lite2-update].

Для Станции 2 данные получены от [автора адаптации][alisa-station2-pr]: прошивка
`0.369.1.46.4778263334.20261013.295`, Windows 11 / Edge, голосовой диалог,
команды открытия/закрытия и автозапуск. Эта модель имеет внутреннее имя yandexmidi;
розничная [Станция Миди](../devices/station-midi.md) — другая модель и не поддерживается.
Собственного аппаратного прогона Станции 2 в проекте нет.

### Что понадобится { #chatgpt-req }

- Лайт 1, Лайт 2 или [Станция 2](../devices/station-2.md) с уже работающими
  [root и SSH](../start/ssh.md).
  Колонка должна быть доступна из сети ПК.
- Для установки с Linux — x86_64, Python 3.10+ и Chromium для первого входа.
- Для установки с Windows — x64 и Edge или Chrome для первого входа.
  Python и SSH-библиотеки входят в пакет.
- Для моста — Лайт 2 и Linux-ПК с PipeWire-Pulse или PulseAudio, включённый всё время работы.
- Аккаунт ChatGPT с доступным голосовым режимом и доступ колонки к сервисам Алисы.
- На колонке должен работать штатный Quasar и проигрыватель aplay из ALSA; для моста нужен socat.

Мастер проверяет модель, SHA-256 maind и библиотеки VQE, свободное место и компоненты.
Неизвестная сборка поддерживаемой модели допускается с предупреждением; совместимость её звука
и команд остаётся непроверенной. [Проверки прошивки][alisa-firmware].
Готовые ARM-модули входят в релиз: Clang и LLD для установки не нужны. Недостающие пакеты
на ПК предлагается установить через pacman, apt-get или dnf. Из этих семейств полный
живой прогон выполнен только на CachyOS.

### Как подключить { #chatgpt-setup }

1. Запустите установщик на компьютере:

    === "Linux"

        ```sh
        curl -fsSL \
          https://raw.githubusercontent.com/rison1337/Alisa-ChatGPT-voice-assistant/main/bootstrap-linux.sh | sh
        ```

    === "Windows"

        Скачайте [Windows-пакет][alisa-windows-download] из релиза 0.3.3, распакуйте папку
        целиком и запустите START-WINDOWS.cmd. Установка приложения не требует прав администратора.

2. В Linux выберите нативный режим или мост; в Windows доступен нативный режим.
3. Укажите IP, порт и пароль SSH колонки. После проверки мастер создаёт отдельный ключ;
   параметры подключения запоминаются, пароль не сохраняется. Псевдоним alice не нужен.
4. Выберите автозапуск, голосовые фразы и подсветку. В нативном режиме можно добавить
   VLESS для GPT по отдельной ссылке или подписке с выбором сервера.
   На Станции 2 настройка подсветки GPT пропускается: её панелью управляет штатная Алиса.
5. Подтвердите установку после просмотра размера компонентов и свободного места.
6. Войдите в ChatGPT в открывшемся окне браузера. Вход обнаруживается и сохраняется
   автоматически; закрывать окно вручную для подтверждения не нужно.
7. Запустите предложенный короткий тест голосового ответа.

Проверка сети показывает внешний IP и страну выхода: в нативном режиме — колонки,
в мосте — ПК. Для российского IP предлагается VPN. Эта проверка не подтверждает
доступность ChatGPT Voice; для этого служит отдельный голосовой тест после входа.
В нативном режиме после установки и входа ПК можно выключить.

### Команды и настройки { #chatgpt-usage }

| Команда по умолчанию | Что происходит |
|---|---|
| «Алиса, открой чат» | продолжить разговор с GPT |
| «Алиса, создай новый чат» | начать новый разговор |
| «Алиса, открой предыдущий чат» | вернуться к предыдущему разговору |
| «Алиса, закрой чат» | вернуть обычную Алису |

Управление после установки открывается командой:

=== "Linux"

    ```sh
    ~/.local/bin/alisa
    ```

=== "Windows"

    ```bat
    "%LOCALAPPDATA%\AlisaVoice\alisa.cmd"
    ```

В меню доступны смена аккаунта, фразы после «Алиса», автозапуск, обновление и удаление.
На Лайт 1/2 доступна подсветка с живым демо.
Голос нативного клиента выбирается в CLI, голос моста — на сайте
ChatGPT. Смена фраз и цвета применяется без перезапуска текущего разговора.
В нативном режиме Лайт 1/2 голубая волна в паузах выключена по умолчанию. Её включает отдельная
галочка «Настройки → Подсветка в паузах GPT»; анимация ответа выбирается отдельно.

Оба режима можно держать установленными. Перед запуском другого остановите текущий:
они используют одни микрофоны и динамик. Настройки и входы раздельные; включение
автозапуска одного режима отключает автозапуск другого.

VLESS нативного клиента направляет через туннель только трафик GPT, включая WebRTC.
При потере туннеля прямое подключение блокируется, разговор завершается, управление
возвращается Алисе. Маршруты самой Алисы и SSH не заменяются.

### Обновление программы { #chatgpt-update }

При запуске CLI предлагает новый стабильный релиз: «Обновить», «Не сейчас» или
«Больше не спрашивать». Проверка кэшируется на 6 часов. Для немедленной проверки
откройте «Установка и обслуживание → Обновления программы» или выполните:

=== "Linux"

    ```sh
    ~/.local/bin/alisa update
    ```

=== "Windows"

    ```bat
    "%LOCALAPPDATA%\AlisaVoice\alisa.cmd" update
    ```

Закройте голосовой чат перед обновлением и проверьте IP колонки, если менялась сеть Wi-Fi.
Программа проверяет SSH и компоненты до замены файлов, затем обновляет приложение на ПК
и установленные компоненты колонки. Вход, чаты и настройки сохраняются.
В версии 0.2.0 этого меню нет: повторите установку новым пакетом, затем выберите
«Установка и обслуживание → Настроить / переустановить» для компонентов колонки.

### Ограничения { #chatgpt-limits }

- Это отдельный режим ChatGPT. Команды переключения распознаёт облако Яндекса;
  для входа и выхода голосом нужен доступ к нему.
- Пока идёт разговор с ChatGPT, ответы Алисы подавляются, штатная музыка ставится на паузу.
- Доступность и лимиты задаёт ChatGPT. Распознанные ошибки входа, соединения и лимита
  закрывают разговор и освобождают управление Алисе. Изменения сайта или протокола могут
  потребовать обновления клиента.
- В нативном режиме сессия хранится на колонке, в мосте — в отдельном профиле Chromium
  на ПК. Эти данные не входят в установочный пакет.
- Неизвестная модель, неподходящая архитектура, отсутствие необходимых компонентов
  или ошибка целостности пакета останавливают установку. Разрешение неизвестной сборки
  поддерживаемой модели не подтверждает работу её микрофонов, звука и команд.
- Для Станции 2 доступен только нативный режим, без подсветки GPT. Мост для неё
  останавливается на проверке модели до копирования файлов.

В обоих режимах используется обработанный микрофон VQE.
[Передача VQE на ПК](microphone.md) доступна только на Лайт 2,
[настраиваемая подсветка GPT](led.md#plum-led-rainbow) — на Лайт 1/2.
В нативном профиле Станции 2 обработанный сигнал усиливается в 16 раз по замерам автора;
на Лайт 1/2 уровень сохраняется. При неизвестном состоянии переключателя микрофона
Станции 2 передача звука отключается. [Особенности модели][alisa-station2].

### Как вернуть Алису { #chatgpt-rollback }

Отключите автозапуск выбранного режима и остановите его:

=== "Нативный — Linux"

    ```sh
    ~/.local/bin/alisa native autostart off
    ~/.local/bin/alisa native stop
    ```

=== "Нативный — Windows"

    ```bat
    "%LOCALAPPDATA%\AlisaVoice\alisa.cmd" native autostart off
    "%LOCALAPPDATA%\AlisaVoice\alisa.cmd" native stop
    ```

=== "Мост — Linux"

    ```sh
    ~/.local/bin/alisa bridge autostart off
    ~/.local/bin/alisa bridge stop
    ```

Для удаления программных файлов выберите «Установка и обслуживание → Удалить программу».
Перед удалением показывается состав и создаётся резервная копия. Вход, чаты, root и SSH
сохраняются; выход из аккаунта выполняется отдельно в меню «Аккаунт ChatGPT».
Для удаления только VLESS и его файлов используйте меню «VPN / VLESS».

## Что пока не исследовано { #open }

- Как отличить обычный разговор от команды умного дома внутри голосового соединения.
  Разбор формата есть в [голосовом тракте](../internals/voice.md) и в коде quasard.
- Совместимость гибридного прокси с другими моделями и прошивками: проверен только
  Quasar Bridge на Станции 2.

Свой текст голосом Алисы — задача уже решённая: локально это делает API glagol, см.
[сеть и порты](../internals/network.md#glagol), а на Лайт 2 проверен
[вызов через SSH](sounds.md#native-tts).

## Откат { #rollback }

Для Quasar Bridge, установленного на колонку новым установщиком, сначала верните
исходное подключение Алисы. Выполните на колонке по SSH:

```sh
sh /data/opt/quasar-bridge/app/control.sh rollback
reboot
```

После успешного отката и перезагрузки проверьте, что Алиса снова отвечает. Затем удалите
программу и её автозапуск:

```sh
sh /data/opt/quasar-bridge/app/uninstall.sh
```

Настройки, ключи и журналы остаются в `/data/opt/quasar-bridge`. Удаление откажется
работать, пока не выполнен `rollback`: иначе колонка продолжит обращаться к остановленному
прокси.

Для Quasar Bridge на отдельном хосте, старой установки через YAM и quasard верните
исходный `quasar.cfg` из копии, снятой [перед первой правкой](#compare), и перезагрузите
колонку:

```sh
adb push ./quasar.cfg.orig /system/vendor/quasar/quasar.cfg
adb shell sync; adb reboot
```

Корневая файловая система для записи перемонтируется так же, как при правке:
`mount -o remount,rw /`.

- **Quasar Bridge** — остановить прокси и удалить его пакет, если ставили на колонку
  через YAM.
- **ChatGPT Voice** — остановить выбранный режим или удалить его через CLI, как описано
  в [возврате к Алисе](#chatgpt-rollback).
